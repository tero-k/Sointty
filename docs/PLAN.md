# Sointty: Terminal Hi-Fi Music Player implementation plan

Sointty is the application name. Research snapshot: 2026-09-25. This is a planning document, not an implemented player. Platform order: Linux, then Windows, then macOS. Original project code: `MIT OR Apache-2.0`. At implementation start, record the then-latest stable toolchain as the MSRV in the workspace and CI; Rust 1.98.1 was the latest stable observed during research [Rust releases](https://blog.rust-lang.org/releases/latest/). v1 is complete at M6, including an **opt-in**, lazily opened library index; filesystem browsing never depends on SQLite.


## Implementation status (2026-09-27)
- M1 scaffold: workspace builds; core fidelity/packing rules, Symphonia streaming decoder, ALSA `hw:` backend, ratatui/crossterm TUI, queue/seek engine. Hardware acceptance (DAC, `hw_params`, capture) pending a Linux host.
- M2 code complete: prefill ≥2 periods before start, preopened next track, seamless same-`StreamSpec` transition with boundary-delayed `Playing` event, seek/skip ring replacement, lofty read-only tags shown in TUI, Ogg Opus decoder (feature `opus`, libopus) with RFC 7845 pre-skip/EOS trim and nonzero-gain rejection. 17 unit tests pass on Windows; `opus` feature compilation/tests and the M2 gapless hardware capture are pending a Linux host with `libopus-dev` (`cargo test -p sointty-decode --features opus`).
- M3 code complete: `sointty-playlist` (M3U/M3U8 read+write with relocation-safe relative paths, PLS numeric `FileN` order, XSPF via quick-xml with DOCTYPE/entity rejection, single-image CUE via rcue with INDEX 01 validation and 75 Hz boundary math), remote-URL rejection, ranged CUE playback in the engine (exact span, truncation, gapless adjacent ranges), FIFO queue order, CLI playlist expansion, std-only TUI filesystem browser (no SQLite). 39 unit tests pass on Windows; CUE playback acceptance on hardware pending a Linux host.
- M4 code complete: `ReadAheadSource` (dedicated read-ahead worker, 1 MiB bounded queue, generation-guarded seek, best-effort cancel of blocked kernel reads, self-latching stall state) used for every opened file; engine split into coordinator + decoder worker so Stop/Skip/Seek stay responsive during a stalled read; stall episodes emit `Stalled`, a continuous 2 s stall stops output with `Underrun` and preserves the resume frame, and recovery auto-resumes by re-seek on a fresh ring. 48 unit tests pass on Windows (threading suite stable across repeats); mounted-share acceptance with injected network stalls pending a Linux host.
- M5 code complete (Windows half verified on hardware 2026-09-26): WASAPI exclusive backend on the `windows` crate (the `wasapi` crate cannot express exclusive event mode; replaced in workspace deps), exact-format candidate negotiation (S16/S24 packed→24-in-32/S32/F32, S_OK-only), device-period clamping with retry ladders for real driver quirks, MMCSS promotion, RT loop with zero-fill+xrun accounting, `--list-devices`/`--device default`. Observed on this machine: 3 endpoints enumerated; iFi USB endpoint negotiated exclusive S16Le 44100 Hz; a 3 s fixture played exactly 132300 frames to end-of-queue; clean quit. Remaining: loopback/capture bit-identity and 44.1→96 kHz switch test. macOS Core Audio HAL backend implemented (hog mode, nominal-rate + physical-format set/readback, IOProc); cross-checks clean for x86_64-apple-darwin with 9 pure format-matching tests passing; live-device behavior pending a macOS host.
- M6 code complete (2026-09-26): separate `DsdSpec` end to end (decoder → engine → output; DoP marker fixed to the spec/Linux per-frame alternation), ALSA native-DSD/DoP negotiation with typed rejection when no candidate mode exists, opt-in `ffmpeg-lgpl` extension decoder routing `ape`/`wv`/`tak`/`mpc` + `dsf`/`dff` through FFmpeg with demuxer+decoder availability probing and typed failure when absent (verified against an LGPL FFmpeg 9.0 build: all six formats decodable, `dff` demux unavailable and reported), opt-in `library-index` SQLite crate (lazy open, incremental scan stats, `--index`/`--reindex DIR` CLI with one root per flag). 93 unit tests pass on Windows; feature matrix builds clean (default, `library-index`, no-FFmpeg, combined). Pending a Linux host: native-DSD/DoP `hw_params` acceptance and per-binary LGPL audit of the distributed FFmpeg build.
- UI fixes (2026-09-26): the browser's `Enter` only enqueued and never sent `Play`, so TUI-started playback was impossible; playback keys were swallowed while the browser pane was open. Enqueue now auto-starts playback, play/pause/stop/next/seek work in every pane, a `d` device picker drives the previously unreachable `SelectDevice` command and persists the choice to `<config dir>/sointty/config.toml` (`device`/`period_frames`/`buffer_frames`; CLI flags override), and Linux gained `--list-devices` via a std-only `/proc/asound/pcm` parser. Configure-time `eprintln!` diagnostics in the WASAPI/ALSA backends were removed because they corrupted the TUI alternate screen; negotiated parameters are shown via `OutputSpec`. 104 unit tests pass on Windows; live pty verification on this machine: endpoint picker selection persisted to the config file and was reloaded on next launch, 44.1 kHz fixture played to end-of-queue, clean quit.
- Playback failure fix (2026-09-26): `spec_from_params` had hardcoded S16 for every Symphonia file; f32/24-bit decoded blocks were rejected by `pack_exact` after opening the wrong device format. `SymphoniaDecoder::open` now takes the declared sample format or primes its first decoded block (as the FFmpeg adapter does), maintains the first block across `next_block`, checks midstream encoding changes, and interleaves S24 samples correctly. Command-path and auto-advance errors now emit `PlayerEvent::Error` and leave the worker alive; the TUI exposes them and treats space as Play after failure. Windows iFi live checks: 3 s S24 WAV negotiated S24In32High and emitted 132300 frames; 3 s FLAC decoded S32 and emitted 132300 frames; MP3 decoded F32 but was visibly rejected with `no exact exclusive format` because that endpoint has no exclusive F32 (conversion remains forbidden). 111 unit tests passed on Windows; digital capture/bit identity still pending.
- Read-ahead race fix (2026-09-26): on a seek during an in-flight read, stale data was generation-checked but stale EOF/read errors were not. That could mark the new generation EOF and produce intermittent `decode failed` on the first browser attempt. All read outcomes now honor the generation; a gated regression covers stale EOF and error. The staged Windows binary in `dist/sointty.exe` played a 24-bit FLAC from the filesystem browser on its first attempt after the fix. 112 unit tests pass on Windows; format-dependent hardware and digital-capture acceptance remain pending.
- WASAPI click fix (2026-09-27): the iFi USB driver rejects any event-mode period below the buffer duration (`AUDCLNT_E_INVALID_DEVICE_PERIOD`, including after a whole-millisecond period retry added in `init_attempts`), then reports padding as binary full/empty and fires the event only when the buffer is already exhausted; every write delay became an audible click once per buffer (observed at 88.2–192 kHz where frame-derived periods are fractional milliseconds; 44.1 kHz's exact 50 ms period was accepted). When the driver forces period == buffer, `configure` now re-activates the endpoint in push mode (no `EVENTCALLBACK`, granular padding returns) and the render thread tops up on a quarter-buffer waitable timer; whole-buffer event mode with timer assist remains the last resort if push init fails. The render cadence decision moved to `configure` using the ACTUAL `GetBufferSize` result; the driver bumped a requested 8820-frame buffer to 15360 frames at 192 kHz, which silently disabled the timer when the decision was recomputed from requested values. The device buffer is also pre-filled before `Start`. Verified on the iFi: 96/88.2/192 kHz transitions fault-free, periodic clicks gone by ear. Workspace: 121+ tests pass; `dist/sointty.exe` restaged.
- TUI/library milestone (2026-09-27): the browser remembers its last folder across launches (saved in `config.toml`, falling back to home, never the process cwd) and `A` adds a whole folder recursively (audio files only, deterministic order, atomic save; a folder removed mid-add aborts without a partial write). A Locations pane (`l`) lists home, drives and mount roots; Windows enumerates letters via `GetLogicalDrives`, labels mapped drives via `WNetGetConnectionW`, maps with the OS credential prompt (`WNetAddConnection2W`, `CONNECT_INTERACTIVE`) and disconnects via `WNetCancelConnection2W`; Linux/macOS mount SMB shares through `gio`/`open` with the URI as a single argument. Named playlists persist in `<data dir>/sointty/playlists.toml` (selected index, ordered entries, CUE ranges, atomic write, malformed files never overwritten); adding to a playlist never touches the live queue. The player publishes `QueueChanged` snapshots (audible track plus pending FIFO) rendered in a queue view (`Tab`), and pump/output failures clear the audible/current snapshot so a failed track never looks playable. Buffer timing is per track in Auto (derived from each decoded rate) and adjustable under `m` > DAC settings with period/buffer validation in both TUI and engine. Canceling or failing a Locations path/map/mount prompt restores the Locations pane. 167 workspace tests pass on Windows; live pty smoke: browser opens at home, device auto-selected, clean quit.
- TUI navigation/progress update (2026-09-27): browser `Backspace` at a filesystem root opens Locations for drive changes, while `Esc` returns to the same browser selection. The visible saved playlist is focusable with `f`; Up/Down choose an entry and Enter appends it to the independent live queue, starting playback when idle. Playback displays played/total time and a width-aware text progress bar; Symphonia uses its playable `Track::num_frames`, explicit CUE spans are bounded by the file length, and unknown totals remain `--:--` without a fabricated file-size estimate. Length events follow audible gapless boundaries, and the TUI rejects stale track IDs.
- FLAC bit-depth fix (2026-09-28): Symphonia's FLAC decoder widens every sub-32-bit stream into left-aligned S32 buffers, so `SymphoniaDecoder` reported S32 for 16- and 24-bit FLAC; macOS devices offering only S16 or 24-in-32 physical formats were then rejected ("no offered physical format preserves the stream exactly"), while Windows drivers silently accepted the S32 container. The decoder now reads the codec's declared bits per sample (the FLAC codec amends its params from STREAMINFO, so Ogg-FLAC is covered too), reports the exact source encoding (S16/S24), and undoes the widening with an arithmetic right shift on the decoder thread; each shifted sample is checked against its widened value, and a nonzero low bit is a decode error, never a silent truncation. True 32-bit FLAC stays S32 full-range. Inline-generated FLAC fixtures (verbatim frames, CRC-8/CRC-16) cover exact 16/24/32-bit round-trips. 183 unit tests pass on Windows; the recovered S24 spec drives the existing Core Audio 24-in-32 physical-format matching, hardware playback on macOS pending a Mac.
- Core Audio format-enumeration fix (2026-09-28): `kAudioStreamPropertyAvailablePhysicalFormats` returns `AudioStreamRangedDescription` (ASBD plus a min/max rate range), but the HAL read the property as plain ASBDs; every entry past the first was misaligned garbage, so no candidate ever matched and every macOS playback attempt failed with "no offered physical format preserves the stream exactly". The backend now reads ranged descriptions, matches the requested rate inside the inclusive range (a fixed rate is a degenerate range), pins the exact rate on the physical format, and keeps the readback equality check as the exact-rate guarantee. Verified by cross-checking the workspace for `x86_64-apple-darwin` and by range-matching unit tests; hardware playback on macOS pending a Mac.
- Core Audio hardening and diagnostics (2026-09-28): on one USB DAC the stream played garbled and fast after the ranged-description fix, consistent with the device running a different format/rate than negotiated. `configure_inner` now re-reads the nominal rate and physical format after the buffer-frame-size change (a known driver reset point), re-applies both once on mismatch, and fails configuration if the device still does not hold the exact format. The configure-time buffer-size `eprintln!` (which corrupts the TUI alternate screen) moved into an opt-in diagnostic log: setting `SOINTTY_COREAUDIO_LOG=/path/to/log` records the requested spec, every offered ranged physical format, the chosen/readback/settled ASBDs, and first-callback buffer geometry. The HAL callback stores the geometry in atomics; `stop` writes it to the log. 184 workspace tests pass on Windows; macOS cross-check (`x86_64-apple-darwin`) compiles; hardware verification pending a Mac.
- Core Audio S24 container fix (2026-09-28): the diagnostic log showed an iFi USB DAC offers no 24-in-32 physical format, so S24 matched the packed 3-byte 24-bit entry; the driver accepted the property (readback matched) but the HAL IO path kept delivering 4-byte-frame buffers (32768 bytes at frame size 4096), so playback ran 4/3x too fast and garbled. Packed 24-bit formats are no longer matched on macOS; S24 now also matches a signed 32-bit slot, written top-aligned with zero low bits (the exact integer widening the fidelity contract permits; `OutputSpec` reports 24 valid bits). The MacBook internal output offers only 32-bit float, so integer streams stay rejected there unless an opt-in conversion mode is added. 185 workspace tests pass on Windows; macOS cross-check compiles; DAC hardware verification pending.
- Integer-to-F32 compatibility mode (2026-09-28): the MacBook internal output (and any float-only endpoint) rejected every integer stream, so FLAC/PCM playback was impossible there even though the fidelity contract permits an explicitly opted-in conversion. Mirroring the existing F32-to-integer opt-in, a new mode (CLI `--allow-int-to-float`/`--no-int-to-float`, persisted `int_to_float` in `config.toml`, TUI `i` key plus a DAC-settings row) negotiates exact-rate/layout F32 only after the exact integer attempt fails; conversion runs on the decoder worker via `pack_int_to_float` (value divided by the full-scale range, no dither), which is exact for S16/S24 (both fit the F32 mantissa) and rounds S32 to 24-bit precision. The `Playing` event's `converted` flag is now driven by a `Conversion` enum so the status line and fidelity label name the actual direction, and disabling a mode mid-track no longer lets a gapless follower inherit the wrong conversion. Tests cover 16/24-bit packing exactness, the S32 rounding boundary, float-only endpoint negotiation with and without the opt-in, TUI toggle persistence, and the config round-trip. 191 workspace tests pass on Windows; hardware verification on a float-only macOS endpoint is pending.
- Core Audio xrun diagnostics (2026-09-30): `SOINTTY_COREAUDIO_LOG=/path/to/log` appends per-run `stop: played_frames=... xruns=... first_xrun_frame=...`. The worker previously cleared `xruns` when reporting an `Underrun`; it now tracks the last reported total without clearing the backend count. The first gap position distinguishes a final partially filled callback from an earlier gap (the final callback still counts as an xrun). The optional `actual rate before start` query may expose a clock mismatch, but neither it nor the nominal readback proves that the DAC emitted sound or was locked throughout playback. Use a fresh log path and one file per run; Mac hardware verification remains pending.
- Core Audio bulk render (2026-10-02): an iFi ZEN DAC V2 reported exact 192 kHz before start and zero ring underruns over about 16 seconds, yet audible distortion remained. The macOS callback was consuming one ring byte at a time (1.536 million pops per second at 192 kHz stereo/32-bit slots), unlike Windows' bulk consumer. It now copies directly into HAL-owned buffers via `pop_partial_slice_uninit` and zero-fills only an unavailable suffix; the packed samples, rate, and format are unchanged. First-callback buffer geometry and priority-promotion failures are captured with atomics and reported by `stop`, never through filesystem or stderr I/O on the render thread. Subsequent Mac hardware playback remained distorted, so per-byte ring pops were not the cause.
- Core Audio IOProc format fix (2026-10-02): the iFi ZEN DAC V2 distortion at 192 kHz survived bulk ring copying because the DAC's *physical* formats are integer-only while its *virtual* (IOProc) format is float-only (`flags=0x9` readback, integer writes did not stick), so signed-integer bytes were being interpreted as float samples. The backend now reads the virtual format, first tries to pin the exact integer ASBD there, and otherwise accepts the canonical interleaved F32 virtual format while keeping the exact integer physical format; the worker then widens integer samples to F32 under the existing `int_to_float` opt-in (exact for S16/S24), and F32-decoded sources pass through as F32 with the HAL quantizing under `float_to_int` (labeled a conversion, not bit-perfect). Any other virtual format fails explicitly. The log records virtual before/readback/settled values. Verified on the iFi ZEN DAC V2 (2026-10-03): 192 kHz S24 FLAC plays cleanly with `int_to_float` enabled.
- Core Audio integer-virtual preference (2026-10-03): an Audirvana diagnostic on a ZEN DAC V2 (macOS 15.5) enumerates non-mixable signed-integer *virtual* formats at all rates, so the DAC's IOProc side may not be float-only after all; the previous runs only ever read the *current* (mixable F32) virtual format and never enumerated `kAudioStreamPropertyAvailableVirtualFormats`. `configure_inner` now enumerates that list, prefers an exact match from it (integer for integer sources: no conversion anywhere), falls back to the current virtual format when it already preserves the stream, and only then to the F32 bridge. The opt-in log records every offered virtual format. Pending Mac retest: if the direct path engages, S24 playback works with `int_to_float` disabled and is bit-perfect end to end.
- Core Audio non-mixable preference (2026-10-03): the ZEN's format lists carry both mixable (`flags=0xc`) and non-mixable (`0x4c`, `kAudioFormatFlagIsNonMixable`) integer entries. mpv's Integer Mode investigation (mpv-player/mpv#6750) documents that integer playback on macOS requires non-mixable integer formats on BOTH the virtual and physical side, and that pairing a non-mixable virtual format with a mixable physical one is silently rejected (dropping the IOProc back to float). The matcher now prefers non-mixable entries among exact matches for both selections. Pending Mac retest with `int_to_float` disabled: success means a fully integer, conversion-free path.
- Core Audio reconfigure settle retry (2026-10-03): with non-mixable Integer Mode active, switching rates (192 kHz to 48 kHz) failed the first reconfigure with `UnsupportedFormat` while an immediate manual retry succeeded: the driver rejects reconfiguration until the stream settles from the previous non-mixable format back to its mixable default. `configure` now retries exactly once after a 250 ms settle delay, only when the device was configured before (`self.spec` set) and the failure was `UnsupportedFormat`; fresh-device unsupported formats still fail on the first attempt. Mac transition retest pending.

## Fidelity contract and limits
- Bit-perfect PCM means preserve each decoder-produced sample's value and sample rate/channel mapping through the application and send that representation through an OS-native direct/exclusive endpoint. Lossless interleaving, endian packing, and exact integer widening with zero-valued low bits are permitted; no lossy narrowing, float/int conversion, resampling, channel remixing, software volume, ReplayGain, EQ, limiter, or dither. Hardware volume/DAC controls are outside the application. MP3/AAC/Opus source bytes are compressed and cannot themselves equal the output PCM; for those formats the reference is the specified decoder's PCM output.
- Support signed S16, packed S24_3LE, 24 significant bits in a 32-bit slot with explicitly negotiated platform alignment/valid-bit metadata, and S32; additionally offer native IEEE F32 for decoders producing f32. Reject an f32-decoded stream on an integer-only endpoint with `UnsupportedFormat`, rather than converting it, unless the user explicitly opts in to F32→integer conversion (`--allow-float-to-int`, persisted `float_to_int`, TUI `c`), a clearly labeled non-bit-perfect compatibility mode implemented 2026-09-26. Confirm exact rate, channels/channel mask, packing and valid bits at initialization. No `cpal`, ALSA `plug`/`plughw`/`default`, WASAPI shared mode, or Core Audio system mixer/AudioUnit path. Use a selected physical endpoint; do not silently switch devices or use a Core Audio aggregate. Hardware/driver/DAC DSP and analog behavior cannot be proven by an application-level contract; state the tested boundary.
- The actual device write/commit is unavoidable output I/O: the RT path prohibits filesystem, network, logging and database I/O, allocations, locks, waiting on control channels and unbounded work; ALSA PCM writes, WASAPI render-buffer commits and writes into Core Audio's supplied callback buffers are the sole output-I/O exceptions. Event-driven or blocking device waits should sleep, not busy-spin. A finite buffer reduces jitter, **cannot guarantee** that no arbitrarily long SMB/NFS stall starves playback; surface an underrun rather than claim bit perfection through a gap.

## Proposed public interfaces (signatures, not implementation)
These are workspace-owned interfaces, **not** claims about existing crate APIs. `SourceError`, `DecodeError`, `OutputError`, `PlayerError`, `TrackId` and `DeviceId` are typed error/identity values. The `AudioOutput` instance owns one selected `DeviceId`. Platform modules implement exactly the same trait; no `cpal` shim.

```rust
pub enum SampleEncoding { S16, S24, S32, F32 }
pub struct ChannelLayout { pub channels: u16, pub mask: u32 }
pub struct StreamSpec { pub rate_hz: u32, pub layout: ChannelLayout, pub encoding: SampleEncoding }
pub enum DeviceFormat { S16Le, S24_3Le, S24In32Low, S24In32High, S32Le, F32Le }
pub struct OutputSpec { pub device: DeviceId, pub rate_hz: u32, pub layout: ChannelLayout, pub format: DeviceFormat, pub valid_bits: u8 }
pub struct BufferConfig { pub period_frames: u32, pub buffer_frames: u32, pub ring_frames: u32 }
pub struct OutputCounters { /* preallocated atomics: played frames, xruns, fault flags */ }
pub trait AudioOutput: Send {
    fn configure(&mut self, input: &StreamSpec, buffers: BufferConfig) -> Result<OutputSpec, OutputError>;
    fn start(&mut self, pcm: rtrb::Consumer<u8>, counters: std::sync::Arc<OutputCounters>) -> Result<(), OutputError>;
    fn stop(&mut self) -> Result<(), OutputError>;
}
pub trait Source: std::io::Read + std::io::Seek + Send {
    fn size_hint(&self) -> Option<u64>;
}
pub enum DecodedPcm<'a> { I16(&'a [i16]), I24(&'a [i32]), I32(&'a [i32]), F32(&'a [f32]) }
pub struct DecodedBlock<'a> { pub spec: StreamSpec, pub frames: u32, pub pcm: DecodedPcm<'a> }
pub trait Decoder: Send {
    fn spec(&self) -> StreamSpec;
    fn next_block(&mut self) -> Result<Option<DecodedBlock<'_>>, DecodeError>;
    fn seek_to_frame(&mut self, frame: u64) -> Result<u64, DecodeError>;
}
pub enum PlayerCommand { Enqueue(std::path::PathBuf), Play, Pause, Stop, Next, SeekFrame(u64), SelectDevice(DeviceId), Quit }
pub enum PlayerEvent { Playing { track: TrackId, output: OutputSpec }, Position { track: TrackId, frame: u64 }, Paused, Reconfiguring, Underrun { track: TrackId }, Stalled { track: TrackId }, Error { track: Option<TrackId>, kind: PlayerError }, EndOfQueue }
```

`DecodedPcm` slices are interleaved in `ChannelLayout` order; I24 uses sign-extended 24-bit values. The decoder/packer must reuse a bounded scratch buffer. `OutputSpec` captures device packing/valid bits and is the **actual** established configuration, not a requested nearest rate. Extend the decoder/output type model with a distinct `DsdSpec` at M6; never disguise DSD as PCM. Reject an absent/ambiguous channel layout rather than rearranging channels without a verified one-to-one map.

## Threads, ownership and state changes
- UI/main owns terminal and screen state; `crossterm` events and player events wake redraw, with a position refresh at 4 Hz only while playing, no constant idle polling. Bounded crossbeam channels carry UI commands/player events. The non-RT player coordinator owns queue, track IDs, boundary decisions, state transitions and device control; it does not block the UI on device reopening or file reads.
- A streaming decoder worker owns exactly one current decoder, optionally a second preopened/predecoded next decoder and their `Source`s, and the **one** SPSC producer. A separate cancellable I/O read-ahead worker handles blocking mounted-share reads through a capped 1 MiB read-ahead queue (also usable for local files). Decoder consumption is at most ring capacity, not whole-file buffering. An OS-mounted SMB/NFS path is a normal `FileSource`; native SMB/NFS/HTTP/WebDAV are later transport implementations. Commands take precedence when the producer has no free frames; wait for a bounded wakeup rather than spinning. Coordinator remains responsive when an OS-mounted path stalls; cancellation of a blocked kernel read itself is best-effort.
- Output backend owns `rtrb::Consumer<u8>` after `start`. On Linux one dedicated PCM output thread waits/writes; Windows one event-driven WASAPI render thread (device-supported polling is a documented exception if exclusive events do not work); macOS a device-bound HAL IOProc callback invoked by the OS, not a pretend universal `std::thread`. All scratch, PCM bytes, device handles, callback context and atomic telemetry are allocated before start. No `crossbeam-channel` send, locks, heap operations, formatting, panics, `println!`, SQLite, filesystem/network reads or log calls in a real-time cycle; the manager polls atomics and publishes human-readable events off-thread. Audio-device writes/callback-buffer filling are necessary exceptions. Request RT priority best-effort and surface failure without switching to mixed output.
- Initial defaults: hardware period 50 ms, hardware buffer 150 ms, ring 250 ms (rounded to legal whole frames/hardware limits); prefill at least two periods before starting. Configurable frame counts; cap memory as `ring_frames × channels × bytes_per_device_sample` plus bounded per-track decoder scratch and the 1 MiB compressed read-ahead queue. Endpoints may force other legal timing: report the actual values. On seek/skip/stop, coordinator stops the backend, discards both old ring endpoints and allocates a new ring/prepares and prefills the destination off-RT, since [`rtrb::Consumer` has no flush method](https://docs.rs/rtrb/latest/rtrb/struct.Consumer.html); old generations cannot replay. Seek into a compressed file starts at the codec seek point, decodes/prerolls and discards up to the requested absolute PCM frame; CUE offsets use the same frame clock.

## Native negotiation, transitions, failures
1. Select the explicit endpoint and probe the first decoded block/spec before opening output. Build only exact-rate, same-channel/layout candidate formats: native S16/S24_3LE/S24-in-32/S32 as compatible with original integer precision, native F32 only for f32 PCM. If source 24-bit, reject a device offering only S16. Byte packing and one-to-one widening may run on the decoder thread; preserve sample values with no gain/resample/dither. Reject lossy conversion. A different device rate is an error, **never** an invitation to `set_rate_near` and play at the nearest value.
2. ALSA: open `hw:CARD,DEV`, set exact rate/channels/format with `alsa` HwParams; read back committed rate, layout, format, significant bits, periods and buffer. [`hw` is raw while `plug` converts](https://www.alsa-project.org/alsa-doc/alsa-lib/pcm_plugins.html). Windows: select the requested endpoint, use [exclusive `IsFormatSupported`](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-isformatsupported) (try appropriate `WAVEFORMATEX` and `WAVEFORMATEXTENSIBLE` descriptors for mono/stereo and valid bits), then exclusive `Initialize` with exact format and legal event period/buffer; no shared-mode closest match. Core Audio: acquire `kAudioDevicePropertyHogMode`, check/set/read back nominal rate **and physical stream format** via `AudioObject*` APIs; register `AudioDeviceCreateIOProcID` on that `AudioDeviceID`. Do not use deprecated `AudioDeviceSetProperty` or assume hog/rate alone bypasses HAL conversions [Apple TN2223](https://developer.apple.com/library/archive/technotes/tn2223/_index.html); reject unsupported/unverified device paths. Restore a changed nominal rate/release hog on clean shutdown when safe (do not override a rate another client changed meanwhile).
3. Decoder worker preopens next track while current remains buffered and prepares decoded blocks, respecting frame-accurate codec gapless trim. Compare next track's **actual `OutputSpec`** against the active one (device, sample rate, channel count/map, packing, valid bits). If identical, append next frames to the *same* producer with no stop/reopen and with a frame-count boundary marker kept on the control plane; backend runs continuously and playing event changes only after actually consumed frames. Same format is necessary, not sufficient: absent next data or missing exact trim means report an interruption instead of falsely calling it gapless. If different, finish/drain the old track to its last audible frame, stop it off-RT, release/reconfigure the endpoint to the next exact rate/format, create a fresh ring, prefill and start; report `Reconfiguring`, and do not promise zero-silence across a hardware rate switch. For CUE tracks referencing the same continuous image, don't reopen or insert padding at the INDEX 01 boundary.
4. Error policy: `UnsupportedFormat { rate, channels, encoding }` or device busy/hog denied → leave that track stopped, show requested vs supported, never fall back to `default`/shared/resampled playback; next track requires explicit user action. Device lost/disconnected or XRUN → stop stream, mark position/bit-perfect continuity invalid, emit `Error`/`Underrun`, discard old ring and require user retry/reselect (never mask a gap as success). Network/read-ahead starvation → `Stalled` and explicit underrun; after a configurable 2-second empty-buffer/read timeout, stop and preserve seekable resume position, allow retry once source returns. If automatic silence is required by a native callback while handling underrun, count/report it as non-bit-perfect interrupted playback, never as silent success. Queue empty/missing file/invalid or unreadable playlist reference → typed error and stay responsive; missing SMB mount is a local-path I/O error. Priority escalation failure is a warning, not a mode fallback.

## Playlists, CUE and optional index
- `playlist` reads/writes M3U and UTF-8 M3U8 (preserve order, relative file paths based on playlist directory where same-root representability permits; otherwise absolute/file URI), reads PLS `FileN` order and XSPF `<location>` using `quick-xml` with no external entity resolution, and rejects remote URLs rather than silently opening network protocols. Distinguish relative filesystem paths from `file://` URIs; resolve only against containing playlist. M3U/PLS are small line-oriented formats: implement these within `playlist` rather than rely on [m3u 1.0.0](https://crates.io/crates/m3u), last released 2017 with no verified coverage of this path policy.
- Read single-file album CUE with `rcue`; validate `FILE`, ordered `TRACK` and `INDEX 01` entries, reject ambiguous metadata affected by its known REM indentation limitation. Convert MM:SS:FF to CD frames at 75 Hz, then track start `floor(cd_frames × decoded_rate / 75)`; end is next INDEX 01, final end is source EOF. Do not inject fake silence or discard source samples at `INDEX 00`; image bytes before first INDEX 01 and between INDEX 00/01 remain in the preceding audible span (for track 1, begin from frame 0). At 44.1 kHz a CD frame is exactly 588 samples; at other sample rates the floor rule gives the nearest earlier sample, not impossible sub-sample accuracy. Validate monotonic/in-bounds indices and reject referenced files that are missing or not a single continuous image. CUE UI positions are relative to the virtual track, seeks use absolute source frames.
- Default browsing enumerates the filesystem without opening SQLite. When `library-index` is explicitly enabled at M6, `crates/library` uses `rusqlite` with the `bundled` feature, on-demand creation and bounded batch scans, keeps connections off RT, and tolerates removed mounts by marking entries unavailable; disabling the feature builds/runs browser mode without SQLite. Use stable path + file identity/mtime for incremental refresh; preserve browser behavior if the DB is missing or corrupted by reporting the index error and allowing browsing without it.

- Decoder golden tests: store small redistributable fixtures or generated lossless references and SHA-256 over canonical **decoded** interleaved PCM bytes (endianness and valid-bit alignment fixed in fixture metadata). Include FLAC/ALAC/WAV/AIFF/MP3/AAC-LC/Vorbis/Opus and later FFmpeg codecs; golden hashes are decoder-version-specific for lossy codecs. ## Risks and open questions for review
- No selected DAC, network mount or native macOS hardware is available in this planning workspace; exact supported rates, float/24-bit layouts, physical Core Audio stream access, exclusive event support, hardware volume and digital-capture options remain **device-specific observations**, not guessed guarantees. A no-conversion error is required when negotiation or readback cannot establish the requested path.
- Native F32 is required for Symphonia's [MP3 f32 decoder](https://docs.rs/symphonia-bundle-mp3/0.6.1/src/symphonia_bundle_mp3/decoder.rs.html); files decoded to f32 are refused on integer-only hardware unless the user opts in to labeled F32→integer conversion. Strict refusal remains the default. Opus nonzero header gain is likewise rejected while software gain is forbidden.
- Codec/container-level gapless metadata is inconsistent; only prove gapless for fixture combinations with exact trim. Different-rate device reopening inherently interrupts output. Network jitter can exceed any finite read-ahead, and an OS-mounted share read may not be cancellable until the kernel returns.
- Core Audio hog mode does not by itself prove integer bit preservation. FFmpeg's LGPL/GPL distribution obligations and build-specific demuxer/decoder availability require per-binary audit; the GPL feature must not enter the default dual-licensed release. `rcue`'s parser limitation requires targeted CUE corpus validation; maintain test fixtures for the supported single-image syntax.
